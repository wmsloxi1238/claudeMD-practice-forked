## 새로 배운 내용
- `git branch <name>`은 HEAD가 가리킬 커밋이 없으면 실패한다. 빈 레포에서는 첫 커밋이 있어야 브랜치 생성 가능.
- `git pull`이 충돌을 일으키는 경우, 충돌 마커(`<<<<<<<`, `=======`, `>>>>>>>`)를 직접 편집해서 해결한 뒤 add → commit 해야 머지가 완료된다.
- Git의 fetch URL과 push URL은 다르게 설정할 수 있다. `git remote -v`에서 두 줄로 보이는 이유.

## 오늘의 도전 과제와 해결 방법
**문제**: `git push origin main` 실행 시 `! [rejected] main -> main (fetch first)` 에러 발생.
**원인**: 원격에서 GitHub 웹으로 README를 수정한 커밋이 있어 로컬과 분기됨.
**해결**: `git pull --no-rebase origin main`으로 머지 시도 → 충돌 발생 → README.md를 직접 열어 충돌 마커 제거하고 원하는 버전으로 정리 → `git add` + `git commit` + `git push`로 마무리.

## 오늘의 회고
- 같은 파일을 로컬과 원격에서 동시에 수정하면 충돌이 거의 확실하다. 작업 전에 `git pull`을 먼저 하는 습관을 들이자.
- 충돌이 발생해도 당황하지 말고 충돌 마커를 차분히 읽고 정리하면 된다.
